# STM32F411 Bootloader + OTA 项目需求说明书

## 1. 项目概述

本项目基于 STM32F411CEU6，实现一套具备 Bootloader、后台 OTA 固件下载、A/B 镜像管理、固件校验、版本切换、运行确认和失败回滚能力的嵌入式固件升级系统。

项目目标不是实现简单的 Bootloader 跳转 Demo，而是通过完整升级链路学习和验证：

Boot Process

- Firmware Transfer
- External Flash Storage
- Firmware Validation
- Boot State Management
- Trial Boot
- Confirm
- Rollback
- Watchdog
- Logging / Diagnostics

Application 在正常运行期间负责后台接收 OTA Firmware，并将新固件保存至外挂 Flash。

固件下载过程中不影响当前 Application 的正常运行。

下载完成后，Application 设置升级请求并执行 Reset。

Bootloader 在下一次启动时完成新固件校验、安装和启动。

因此，本项目中的“后台无感 OTA”定义为：

```text
Application运行
      │
      ├── 正常业务继续运行
      │
      └── 后台接收Firmware
                │
                ▼
         External Flash
                │
          下载完成并校验
                │
                ▼
          设置Pending状态
                │
              Reset
                ▼
           Bootloader
                │
             安装升级
                │
                ▼
            New APP
```

不要求实现运行时热替换。固件真正切换时允许发生一次设备 Reset。

------

## 2. 硬件平台

项目固定使用以下硬件平台：

| 硬件                              | 接口       | 项目职责                         |
| --------------------------------- | ---------- | -------------------------------- |
| STM32F411CEU6                     | MCU        | Bootloader、Application、OTA控制 |
| 外部 SPI NOR Flash（板载 W26Q64） | SPI        | OTA A/B Firmware 镜像存储        |
| AT24C02 EEPROM                    | I2C        | Boot / OTA 掉电状态及 Metadata   |
| CK02AT                            | I2C        | 预留安全实验，不作为 V1 核心依赖 |
| J-Link                            | SWD        | 烧录、调试                       |
| SEGGER RTT                        | SWD/J-Link | Bootloader 和 APP 调试日志       |
| LED                               | GPIO / PWM | Firmware V1.0 / V1.1 功能验证    |
| UART                              | UART       | OTA Firmware 传输                |
| IWDG                              | MCU内部    | Trial Boot 和 APP 启动失败检测   |

CK02AT 因缺少可靠公开 Datasheet，V1 不要求接入正式 OTA 安全链。

## 4. Flash 总体架构

### 4.1 STM32 Internal Flash

内部 Flash 负责：

```text
Internal Flash
│
├── Bootloader
│
└── Running Application
```

V1 不在内部 Flash 保存两个完整 Application。

Bootloader 与 APP 采用独立 Flash Sector。

当前 APP 起始地址可以继续采用：

```text
APP_START = 0x08010000
```

具体地址在 Flash Layout 设计阶段最终确认。

------

## 5. External Flash A/B 方案

外部 SPI NOR Flash 实现 A/B 双镜像槽。

逻辑结构：

```text
External Flash
│
├── Slot A
│      Firmware Image
│
├── Slot B
│      Firmware Image
│
└── Reserved
```

A/B 不永久代表“新版本”和“旧版本”。

它们的角色根据当前升级状态动态变化，例如：

```text
Slot A
V1.0
Confirmed

Slot B
Empty
```

收到 V1.1 后：

```text
Slot A
V1.0
Confirmed
Rollback Image

Slot B
V1.1
Pending
```

V1.1 成功运行并确认后：

```text
Slot A
V1.0
Previous / Rollback

Slot B
V1.1
Confirmed
```

下一次 V1.2 OTA 时，可以重新使用 Slot A：

```text
Slot A
V1.2
Pending

Slot B
V1.1
Confirmed
```

因此形成真正的：

```text
A ↔ B
```

交替升级机制。

------

## 6. AT24C02 Metadata

AT24C02 用于保存掉电、Reset 后仍然必须保留的系统状态。

典型信息包括：

```text
Current Version

Confirmed Version

Pending Version

Active Slot

Confirmed Slot

Pending Slot

Firmware Size

Firmware CRC

Upgrade State

Trial Boot State

Boot Failure Count

Rollback Request

Metadata CRC
```

V1 不立即冻结具体 `struct` 定义。

Metadata 必须满足：

```text
Reset后可恢复

掉电后可恢复

能够判断当前启动状态

能够判断是否需要升级

能够判断是否需要Rollback

Metadata自身能够检测损坏
```

后续详细设计阶段研究双副本 Metadata、Sequence Number 和 CRC。

## 7. Firmware V1.0

Firmware V1.0 作为项目初始稳定版本。

功能：

```text
Firmware Version:
1.0.0

Function:
LED Blink
```

运行效果：

```text
LED
ON
↓
OFF
↓
ON
↓
OFF
...
```

建议使用固定周期，例如约 500 ms 翻转一次 LED。

V1.0 同时具备：

```text
OTA Service

Ymodem Firmware Receiver

External Flash Writer

Upgrade Request

Firmware Confirm

RTT + EasyLogger
```

因此 V1.0 不只是 LED Demo，而是整个 OTA 升级链路的起点。

------

## 8. Firmware V1.1

Firmware V1.1 用于验证升级成功。

功能：

```text
Firmware Version:
1.1.0

Function:
PWM Breathing LED
```

通过 Timer PWM 改变 Duty Cycle：

```text
0%
 ↓
100%
 ↓
0%
 ↓
100%
```

形成明显的呼吸灯效果。

这样可以直接通过物理现象判断：

```text
闪烁
=
Firmware 1.0

呼吸
=
Firmware 1.1
```

避免仅依赖串口或日志判断升级是否成功。

Firmware V1.1 同样必须保留完整 OTA 能力，以便后续继续升级 V1.2。

------

## 9. OTA Firmware 传输

第一版 OTA 传输采用：

```text
PC
 ↓
UART
 ↓
Ymodem
 ↓
Application OTA Service
```

Application 接收 Firmware 后：

```text
Ymodem
   │
   ▼
RAM Buffer
   │
   ▼
External Flash Inactive Slot
```

Firmware 不允许直接由 Application 覆盖当前 Internal Flash APP。

这样即使：

```text
传输中断
PC断开
UART异常
Ymodem失败
```

当前运行 Firmware 仍然保持完整。

------

## 10. OTA 下载流程

正常升级 V1.0 → V1.1：

```text
Firmware V1.0
正在运行
      │
      ▼
PC发送 V1.1
      │
    Ymodem
      │
      ▼
Inactive Slot
      │
      ▼
完整Firmware接收完成
      │
      ▼
CRC校验
      │
   ┌──┴───┐
 Failure Success
   │       │
放弃升级   ▼
      设置Pending
           │
          Reset
           │
           ▼
       Bootloader
```

下载失败时不得破坏：

```text
Current Application

Confirmed Firmware

Rollback Firmware
```

------

## 11. Firmware 完整性校验

V1 使用：

```text
CRC32
```

Firmware Payload 在 PC 端生成 CRC。

OTA Metadata 中携带：

```text
Firmware Version
Firmware Size
Firmware CRC
```

Firmware 写入外挂 Flash 后重新计算 CRC。

必须满足：

```text
Calculated CRC
==
Expected CRC
```

才能设置：

```text
PENDING
```

Bootloader 正式安装前应再次执行 Firmware 校验。

因此至少形成：

```text
PC生成Firmware
      │
      ▼
CRC #1
      │
      ▼
传输
      │
      ▼
External Flash
      │
      ▼
CRC #2
      │
      ▼
Bootloader安装前
      │
      ▼
CRC #3
```

CRC 用于错误检测，不代表 Firmware 来源可信。

SHA、AES 和数字签名不属于 V1 强制需求。

------

## 12. Bootloader 启动决策

Bootloader 每次启动需要读取：

```text
Reset Cause
+
Boot Metadata
+
Firmware State
```

根据状态决定：

```text
Normal Boot

Install Pending Firmware

Trial Boot

Rollback

Error / Recovery
```

基本逻辑：

```text
Bootloader
   │
   ▼
读取Metadata
   │
   ├── 无升级请求
   │        ↓
   │     Boot APP
   │
   ├── Pending Image
   │        ↓
   │     Validate
   │        ↓
   │     Install
   │
   └── Trial Failed
            ↓
         Rollback
```

------

## 13. Firmware 安装

Bootloader 安装新的 Firmware 时：

```text
External Flash
Pending Image
      │
      ▼
Firmware Validation
      │
      ▼
Erase APP Sector
      │
      ▼
Read External Flash
      │
      ▼
RAM Buffer
      │
      ▼
Internal Flash Program
      │
      ▼
Internal Flash CRC
```

写入完成后必须重新验证 Internal Flash Firmware。

只有校验成功才能启动新的 Application。

------

## 14. Trial Boot

新 Firmware 第一次启动不能立即认为升级成功。

状态：

```text
PENDING
 ↓
INSTALLING
 ↓
TRIAL
```

Bootloader 安装 Firmware V1.1 后：

```text
Bootloader
   │
   ▼
Firmware V1.1
   │
 Trial Boot
   │
   ▼
Application初始化
```

V1.1 需要完成规定的关键初始化后执行：

```text
firmware_confirm()
```

然后 Metadata：

```text
TRIAL
 ↓
CONFIRMED
```

只有到这里 V1.1 才成为正式稳定版本。

------

## 15. Watchdog

Trial Boot 期间使用 STM32 IWDG 检测 Application 启动失败。

例如：

```text
Firmware V1.1
      │
      ▼
Trial Boot
      │
      ├── 正常运行
      │       ↓
      │    Confirm
      │
      └── HardFault / 死循环
              ↓
          IWDG Reset
              ↓
          Bootloader
```

Bootloader 检测：

```text
Trial State
+
Watchdog Reset
```

则：

```text
Failure Count++
```

达到规定失败次数后执行：

```text
Rollback
```

具体允许失败次数在详细设计阶段确定。

------

## 16. Firmware Rollback

V1 必须支持：

```text
V1.0
 ↓
升级
 ↓
V1.1
 ↓
启动失败
 ↓
Rollback
 ↓
V1.0
```

Rollback Firmware 来源于外挂 Flash 中保留的上一份 Confirmed Image。

例如：

```text
Slot A
V1.0 Confirmed

Slot B
V1.1 Trial
```

V1.1 失败：

```text
Slot A
V1.0
      │
      ▼
Bootloader重新写入Internal Flash
      │
      ▼
V1.0重新运行
```

Rollback 完成后 Metadata 必须恢复到一致状态。

Bootloader 和 Application 继续使用：

```text
J-Link
+
SEGGER RTT
+
EasyLogger
```

必须能够输出关键事件：

```text
Boot Reason
Firmware Version
Active Slot
Pending Slot
Upgrade State
Firmware Size
CRC Result
Flash Erase Result
Flash Program Result
Trial Boot
Firmware Confirm
Watchdog Reset
Failure Count
Rollback
```

日志作为 OTA 状态诊断手段，而不仅是普通调试输出。

## 18. V1 必须完成的异常场景

| 场景                    | 预期行为                    |
| ----------------------- | --------------------------- |
| 无 OTA Firmware         | 正常启动当前 APP            |
| OTA 传输成功            | 保存至 inactive slot        |
| OTA 传输中断            | 保持当前 APP，不升级        |
| OTA Firmware CRC 错误   | 拒绝升级                    |
| Firmware 版本正确       | 允许进入 Pending            |
| External Flash 镜像损坏 | Bootloader 禁止安装         |
| Internal Flash 写入失败 | 不允许标记成功              |
| Trial APP 正常          | Confirm                     |
| Trial APP 启动失败      | Watchdog Reset              |
| Trial 多次失败          | Rollback                    |
| Rollback 成功           | 恢复上一 Confirmed Firmware |
| 普通 Reset              | 不误判为升级失败            |

## 19. V1 烧录与验证实验

### 初始烧录

通过 J-Link 烧录：

```text
Bootloader
+
Firmware V1.0
```

启动后：

```text
LED Blink
```

确认系统当前版本：

```text
1.0.0
```

### OTA Upgrade

通过 UART + Ymodem 发送：

```text
Firmware V1.1
```

V1.0 后台将 V1.1 保存到 External Flash。

下载成功后 Reset。

Bootloader 完成安装。

最终：

```text
LED Blink
 ↓
Reset
 ↓
PWM Breathing LED
```

证明：

```text
V1.0 → V1.1
```

升级成功。

### Rollback Experiment

人为使 V1.1：

```text
不执行firmware_confirm()

或者

启动后主动进入异常状态
```

触发 IWDG。

Bootloader 检测 Trial Boot Failure 后执行 Rollback。

最终：

```text
PWM Breathing
 ↓
Failure
 ↓
Watchdog Reset
 ↓
Rollback
 ↓
LED Blink
```

证明：

```text
V1.1 → V1.0
```

回滚机制有效。

| 防版本降级                   | 后续               |

V1 重点是首先跑通并理解：

```text
Download
→ Store
→ Validate
→ Pending
→ Reset
→ Install
→ Trial
→ Confirm
→ Rollback
```

Firmware V1.1

+

+

+
IWDG
+
Firmware Confirm
+

+

   ↓
OTA V1.1
   ↓
External Flash
   ↓
Bootloader
   ↓
Install
   ↓
Trial
   ↓

   ↓
