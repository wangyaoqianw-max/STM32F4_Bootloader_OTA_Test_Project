# AT24C02 硬件软件接口参考

## 1. 文档目的与边界

本文根据 AT24C02 规格书、用户提供的 AT24C02 原理图片段、PB6/PB7 网络图和当前 Application 工程代码，整理该器件在本项目中的接入方式、协议约束、软件复用边界和待完成事项。

本文是 `S03_EEPROM_Storage` 的硬件软件接口输入，**不是** S03 的冻结设计，也不直接修改生产代码。本文不冻结 Metadata 具体结构、EEPROM 地址分配、双副本策略、任务模型或最终公共 API。

## 2. 结论摘要

| 项目 | 本项目结论 | 状态 |
| --- | --- | --- |
| 器件 | U8，AT24C02，2 Kbit = 256 Byte | 已确认 |

| SCL | `STM32 PB6` → `COMMON_SCL` / `I2C_SCL` → `AHT_SCL` → R26（0 Ω）→ U8 pin 6 | 已确认 |
| SDA | `STM32 PB7` → `COMMON_SDA` / `I2C_SDA` → `AHT_SDA` → R29（0 Ω）→ U8 pin 5 | 已确认 |

| 外部上拉 | 规格书要求 I²C 线路上拉；用户提供片段中未看到上拉电阻 | 必须核对完整原理图/BOM |

## 3. 器件能力与存储边界

| 项目 | AT24C02 规格书约束 | 对本项目的影响 |
| --- | --- | --- |
| 存储组织 | `256 × 8 bit` | 线性地址范围为 `0x00` ~ `0xFF` |
| 总容量 | 2 Kbit = 256 Byte | 只承载状态、计数、版本、Slot 和 CRC 等小数据 |
| Page 数量 | 32 页 | 页地址为 `address / 8` |
| Page Size | 8 Byte | Page Write 单笔最多 8 Byte，且不得跨页 |
| 字地址 | 8 bit | I²C 事务中发送 1 Byte 内存地址 |
| 工作电压 | 1.8 V ~ 5.5 V | `FLSAH_VCC` 必须与 MCU GPIO 电平兼容；不能仅因 EEPROM 支持 5.5 V 就把总线上拉到 5 V |
| SCL 频率 | 规格书列出 5 V 时最高 1 MHz，低电压条件最高 400 kHz | 在电源电压和波形确认前，Software I²C 建议从约 100 kHz 起步 |
| 内部写周期 | `tWR` 最大 5 ms | 每次写入后必须等待器件重新 ACK，或使用有上限的 ACK 轮询 |
| 写入能力 | 字节写、页写 | Driver 必须根据页边界拆分连续写入 |
| 可靠性声明 | 规格书声称擦写寿命 100 万次、数据保持 100 年 | 仍需限制高频 Metadata 写入，不能当作实时日志存储 |

> [!warning]
> Page Write 超过当前页剩余空间时，器件不会自动进入下一页，而会在当前页内回绕并覆盖前面已经发送的数据。Driver 必须在软件中按 8 Byte 页边界拆分，不能直接把任意长度交给底层 `platform_i2c_write()`。

## 4. 板级连接事实

### 4.1 U8 引脚连接

| U8 引脚 | AT24C02 信号 | 原理图连接 | 本项目软件含义 |
| ---: | --- | --- | --- |
| 1 | A0 | GND | 地址位 A0 = 0 |
| 2 | A1 | GND | 地址位 A1 = 0 |
| 3 | A2 | GND | 地址位 A2 = 0 |
| 4 | VSS / GND | GND | 与 STM32 共地 |
| 5 | SDA | R29（0 Ω）→ `AHT_SDA` | 连接至公共 SDA，总线由 PB7 驱动/采样 |
| 6 | SCL | R26（0 Ω）→ `AHT_SCL` | 连接至公共 SCL，由 PB6 产生时钟 |
| 7 | WP | GND | 允许写入；不能通过软件临时锁写 |
| 8 | VCC | `FLSAH_VCC` | 供电；C13 = 100 nF 接在 VCC 与 GND 之间 |

R26、R29 是串联 0 Ω 链路，不是 I²C 上拉电阻。它们应保持装配，否则 U8 与 `AHT_SCL/AHT_SDA` 网络断开，软件探测不到 EEPROM。

### 4.2 STM32 引脚与网络映射

根据用户补充的引脚网络图，当前可确认：

```text
STM32 PB6
   └─ COMMON_SCL / I2C_SCL
       └─ AHT_SCL
           └─ R26 0 Ω
               └─ AT24C02 pin 6 SCL

STM32 PB7
   └─ COMMON_SDA / I2C_SDA
       └─ AHT_SDA
           └─ R29 0 Ω
               └─ AT24C02 pin 5 SDA
```

`AHT_SCL/AHT_SDA` 这个网络命名暗示该总线可能还会连接 AHT 类器件，但当前仓库未以此文档确认总线上是否存在其它从设备。若确实共用总线，所有器件应共用一个 Software I²C 总线对象，由同一个主机串行化访问；AT24C02 和其它从设备通过不同 7-bit 地址区分。

## 5. 电气接入要求

### 5.1 I²C 上拉

AT24C02 的 SDA 为漏极开路输出，规格书说明 I²C 两条线路都需要通过上拉电阻连接到 VCC。用户提供的 U8 局部原理图中没有看到上拉电阻，因此必须检查完整原理图和 BOM，确认上拉是否位于公共总线的其它位置。

要求如下：

- `SCL` 和 `SDA` 都应有上拉到与 MCU GPIO 兼容的总线电源；
- R26/R29 的 0 Ω 不能替代上拉电阻；
- 上拉阻值应结合总线电容、线长、器件数量和目标速率确定；规格书给出的 10 kΩ 可作为单器件低速起始参考，最终以波形为准；
- 若上拉不存在，线路释放后会浮空，ACK、数据 1 和总线空闲态都可能判断错误；
- 若 Software I²C 运行时配置为 `GPIO_NOPULL`，则不能把 STM32 内部上拉当作本板外部上拉的替代品。

### 5.2 GPIO 电气模式

Software I²C 不是普通推挽 GPIO 翻转。PB6/PB7 的目标运行方式应为：

| 状态 | GPIO 行为 | 总线电平 |
| --- | --- | --- |
| 输出 0 | 开漏输出，主动拉低 | LOW |
| 释放 | 开漏输出写 HIGH，或切换为输入 | 由外部上拉拉高 |
| 采样 | 读取实际引脚电平 | 判断 ACK、数据和 SCL 是否真正为 HIGH |

当前工程的 `platform_i2c_init()` 已定义为将 SCL/SDA 配置为“输出 + 开漏 + 无内部上下拉 + 初始 HIGH”，并在释放 SCL 后读取实际电平，以支持 clock stretching。未来 S03 应以该运行时契约为准，不要在 AT24C02 Driver 中直接调用 HAL 操作 PB6/PB7。

上电和 `platform_i2c_init()` 调用前，还应保证 PB6/PB7 不会短暂主动输出 LOW。建议在 CubeMX/`.ioc` 中把基础初始状态也配置为安全释放态；当前仓库中已有的 PB6/PB7 标签和初始 GPIO 代码只是工程基线，不能替代最终的 Software I²C 配置与板级验证。

### 5.3 供电与去耦

- U8 pin 8 使用 `FLSAH_VCC`，其实际标称电压应从板级电源资料或实测确认；
- U8 pin 4 接系统 GND，STM32、AT24C02 和总线上其它器件必须共地；
- C13 = 100 nF，应尽量靠近 U8 的 VCC/GND 引脚；
- AT24C02 支持较宽供电范围，不代表 MCU 的 GPIO 输入输出也能承受同样范围；总线高电平由上拉电源决定，必须以 STM32 GPIO 的电平兼容性为最终约束。

## 6. 器件地址

AT24C02 的器件地址格式为：

```text
| 1 | 0 | 1 | 0 | A2 | A1 | A0 | R/W |
```

本板 A2、A1、A0 全部接地，因此：

```text
7-bit address = 0b1010000 = 0x50
Write address byte = (0x50 << 1) | 0 = 0xA0
Read address byte  = (0x50 << 1) | 1 = 0xA1
```

当前软件接口 `platform_i2c_write()`、`platform_i2c_read()` 和 `platform_i2c_write_read()` 接收的是 **7-bit 地址**，内部会负责左移并拼接读写位。因此调用 AT24C02 时应传 `0x50`，不能传 `0xA0` 或 `0xA1`。

当前硬件地址固定后，单个公共 I²C 总线上不能再通过软件改变这颗 EEPROM 的地址。若以后需要级联多颗 AT24C02，需要在硬件上改变 A0/A1/A2 的电平，并重新核对总线冲突。

## 7. I²C 事务与 Driver 使用方式

### 7.1 字节写

字节写的线序为：

```text
START
→ 0xA0（器件地址 + Write）
← ACK
→ 1 Byte 内存地址
← ACK
→ 1 Byte 数据
← ACK
STOP
→ 内部写周期，最长 5 ms
```

写入完成前，器件可能不响应新的地址。Driver 必须在 STOP 之后等待器件重新 ACK，不能认为收到最后一个数据字节 ACK 就表示非易失写入已经完成。

### 7.2 页写

页写与字节写的前缀相同，区别是 STOP 前可以发送多个数据字节：

```text
START → 0xA0 → 内存地址 → data[0] → ... → data[n-1] → STOP
```

对任意起始地址和长度，Driver 应按以下规则拆分：

```text
pageOffset     = address & 0x07
pageRemaining  = 8 - pageOffset
chunkLength    = min(remainingLength, pageRemaining)
```

每次 `chunkLength` 必须大于 0 且不超过 8。第一笔写完并完成 `tWR` 后，才能开始下一页。不能用一个跨页的长事务依赖器件自动递增地址。

### 7.3 随机读

读取指定地址应使用随机读，即“写入内存地址 + Repeated START + 读取数据”：

```text
START
→ 0xA0
← ACK
→ 1 Byte 内存地址
← ACK
REPEATED START
→ 0xA1
← ACK
← data[0]
→ ACK（如果后面还有数据）
← data[n-1]
→ NACK
STOP
```

这正好对应当前 `platform_i2c_write_read()` 的事务形态：`txData` 为 1 Byte 内存地址，`rxData` 为目标数据缓冲区。读取最后一个字节时必须由主机发送 NACK，再发送 STOP。

### 7.4 顺序读与地址边界

AT24C02 支持连续顺序读，内部字地址会自动递增，但读到 `0xFF` 后会回绕到 `0x00`。为避免上层误把回绕数据当成连续存储，建议公共 Driver API 对读操作执行：

```text
address < 256
length > 0
length <= 256 - address
```

也就是说，跨 `0xFF` 的读操作应返回地址范围错误，而不是依赖芯片回绕。

### 7.5 写周期 ACK 轮询的接口缺口

规格书建议使用 ACK polling 判断内部写周期完成：发送 START 和器件地址，器件在写周期结束后重新 ACK。

当前 `platform_i2c` 公共接口存在一个需要在 S03 设计中处理的边界：

- `platform_i2c_write()` 要求 `length > 0`，并且会在器件地址后继续发送数据；
- 当前没有“仅发送器件地址并判断 ACK”的 `probe` / `is_device_ready` 接口；
- 不能为了轮询而向 `platform_i2c_write()` 传一个伪造数据字节，否则可能真的修改 EEPROM；
- S03 应新增一个明确的地址探测能力，或形成等价的、不会发送数据的底层事务接口；
- ACK 轮询必须有超时上限，至少覆盖规格书的 5 ms 最大写周期并预留软件调度和总线开销。

这项能力属于 Software I²C / Platform 与 AT24C02 Driver 的接口协作问题，不应在 AT24C02 Driver 中绕过 Platform 直接操作 GPIO。

## 8. 与当前工程的映射

当前工程已存在可复用的 Software I²C 基础，但还没有完成 AT24C02 的接入闭环。

### 8.1 已存在的基础

| 工程位置 | 当前能力 | 对 AT24C02 的用途 |
| --- | --- | --- |
| `03_Platform/platform_mcu/i2c/platform_i2c.h/.c` | Software I²C 同步事务、7-bit 地址、START/STOP、ACK、Repeated START、总线恢复 | 承载 EEPROM 的字节和页事务 |
| `04_Impl/impl_bsp/impl_platform_bsp_gpio.c` | `soft_i2c_scl_gpio` / `soft_i2c_sda_gpio` 构造 | 将逻辑 GPIO 绑定到 PB6/PB7 |
| `04_Impl/impl_mcu/impl_platform_gpio.c` | STM32 GPIO 开漏配置、实际电平读取 | 支持释放和采样 I²C 总线 |
| `impl_platform_delay.c` | 微秒级 DWT 延时 | 支持 Software I²C 半周期 |
| `00_Config/project_config.h` | 半周期 5 us、SCL 等待 100 us | 当前约 100 kHz 起步参数和时钟拉伸等待上限 |

### 8.2 当前代码状态与注意事项

- `OTA_APP.ioc`、`Core/Inc/main.h` 和 `Core/Src/gpio.c` 中已有 `I2C_SCL/PB6`、`I2C_SDA/PB7` 的工程基线记录；根据用户最新确认，PB6/PB7 是确定的物理引脚，但 Software I²C 尚未完成可验收配置；
- 当前 `MX_GPIO_Init()` 的生成配置是 GPIO 输出、内部上拉、初始 HIGH；`platform_i2c_init()` 后续会改为开漏、无内部上下拉、初始 HIGH。S03 应确认初始化顺序和上电安全窗口；
- 当前未发现 AT24C02 专用 Driver、容量/页边界校验、写周期等待或 EEPROM 测试调用；
- `platform_i2c` 是同步、阻塞式事务，当前对象本身没有总线互斥。若 `AHT_SCL/AHT_SDA` 确实与其它从设备共用，S03 或后续阶段必须明确同一总线的访问串行化策略；
- AT24C02 是从设备，不能通过 `platform_i2c_init()` 后的普通读写接口自动完成地址探测、写周期等待和页拆分，这些应由 Driver 和 Platform 的明确接口共同完成。

推荐的依赖方向保持：

```text
Application / Service
        ↓
AT24C02 Driver（职责：容量、地址、Page、写周期）
        ↓
Platform I²C（职责：总线时序、ACK、Repeated START、恢复）
        ↓
Platform GPIO / Delay
        ↓
STM32F411 PB6 / PB7
        ↓
AT24C02 U8
```

AT24C02 Driver 不应直接引用 `HAL_GPIO_*`、`GPIO_TypeDef` 或 `main.h`；PB6/PB7 的物理绑定应保留在 BSP/Impl 层。

## 9. S03 推荐接入顺序

以下是可执行的准备顺序，具体接口仍需在 S03 Design 中冻结：

1. 核对完整版原理图/BOM：确认 `FLSAH_VCC` 实际电压、SCL/SDA 外部上拉位置和阻值、R26/R29 是否装配，以及 `AHT_*` 是否为共享总线；
2. 在 `.ioc` 和生成 GPIO 初始化中确认 PB6/PB7 的安全初始态，避免在 Software I²C 初始化前主动拉低总线；
3. 构造一个绑定 PB6/PB7 的 Software I²C Platform 对象，并执行 `platform_i2c_init()`；
4. 增加不带数据的 AT24C02 地址探测/ACK polling 能力，统一传入 7-bit 地址 `0x50`；
5. 实现单字节读写和随机读，再实现按 8 Byte 页边界拆分的连续写；
6. 对 `address`、`length`、`address + length`、页剩余空间和写周期超时做公共入口校验；
7. 只把小容量、低频更新的状态和 Metadata 放入 AT24C02，具体布局和双副本/Sequence/CRC 方案在后续设计中确定；
8. 在真实硬件上用逻辑分析仪确认空闲高电平、`0x50` ACK、随机读的 Repeated START、页写拆分和写周期完成，再做 Reset/掉电保持验证。

## 10. 最小板级验证建议

| 序号 | 验证项 | 操作 | 预期 |
| ---: | --- | --- | --- |
| 1 | 总线空闲 | 上电后观察 PB6/PB7 | SCL、SDA 均为 HIGH，不持续 BUSY |
| 2 | 地址探测 | 发送 7-bit `0x50` | AT24C02 返回 ACK；未占用的其它地址不应误 ACK |
| 3 | 单字节写读 | 写入专用测试地址，再随机读回 | 数据一致；写后经过 ACK polling 才继续 |
| 4 | 页内写 | 在 `0x00`、`0x07` 等位置写入不超过页剩余空间的数据 | 数据不覆盖相邻页 |
| 5 | 跨页写 | 从 `0x07` 写入 9 Byte | Driver 拆为 `1 Byte + 8 Byte` 两笔事务，读回完全一致 |
| 6 | 边界读写 | 测试 `0x00`、`0xFF`，以及越界请求 | 合法请求成功；`address + length > 256` 返回参数错误 |
| 7 | Reset 保持 | 写入测试标记后 Reset，再读取 | 标记保持；总线可重新初始化 |
| 8 | 掉电保持 | 断电/上电后读取已写标记 | 标记保持；硬件电源和测试过程需受控 |
| 9 | 异常恢复 | 人为中断事务或复位后重新初始化 | 平台最多输出 9 个恢复时钟并尝试产生 STOP；最终状态可诊断 |

测试只能使用明确的专用 EEPROM 地址，不要在 Metadata 布局冻结前覆盖真实业务数据。

## 11. 待确认项与禁止假设

### 11.1 待确认项

- `FLSAH_VCC` 的实际电压和上电时序；
- 完整总线上的 SCL/SDA 外部上拉是否存在、阻值、安装状态和连接电源；
- `AHT_SCL/AHT_SDA` 是否与其它从设备共线，以及其它设备地址是否冲突；
- PB6/PB7 的 `.ioc` 最终配置和 `platform_i2c_init()` 的调用时机；
- Software I²C 与其它 Task/服务共享时的互斥或单一 Owner 方案；
- S03 的 ACK polling 接口放在 Platform 还是 AT24C02 Driver 适配边界；
- Metadata 具体布局、版本、Sequence、CRC 和双副本策略。

### 11.2 禁止假设

- 不能把当前仓库的 PB6/PB7 标签当成已经完成的板级功能验证；
- 不能把 R26/R29 的 0 Ω 当作上拉电阻；
- 不能把 `0xA0` / `0xA1` 传给当前接收 7-bit 地址的 Platform I²C API；
- 不能把固定 5 ms 延时写成唯一正确的完成判定，也不能无边界轮询；
- 不能使用带伪数据的普通写事务做 ACK polling；
- 不能让 AT24C02 Driver 直接调用 STM32 HAL GPIO；
- 不能把 AT24C02 当作 Firmware Image 存储器或高频日志存储器；
- 不能在 S03 Design Approval 前冻结 Metadata 结构或把 Bootloader/OTA 状态机提前塞入 EEPROM Driver。
