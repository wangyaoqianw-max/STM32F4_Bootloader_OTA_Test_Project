# AT24C02 硬件软件接口参考

## 1. 文档目的与边界

本文作为 `S03_EEPROM_Storage` 的硬件软件接口输入，整理 AT24C02 在当前 STM32F411CEU6 项目中的已确认硬件事实、Software I2C 复用边界、协议约束和板测要点。

正式冻结设计以：

- `00_Project/03_Stages/S03_EEPROM_Storage/design.md`
- `00_Project/03_Stages/S03_EEPROM_Storage/implementation_plan.md`

为准。

本文不定义 Firmware Metadata 地址布局、OTA 状态、CRC/双副本/Sequence，也不引入 Device Manager 或通用 NVM 架构。

## 2. 已确认结论

| 项目 | 本项目结论 | 状态 |
| --- | --- | --- |
| 器件 | U8，AT24C02，2 Kbit = 256 Byte | 已确认 |
| 总线 | Software I2C，STM32 主机，AT24C02 从机 | 已确认 |
| SCL | STM32 PB6 → 公共 I2C SCL → U8 pin 6 | 已确认 |
| SDA | STM32 PB7 → 公共 I2C SDA → U8 pin 5 | 已确认 |
| 7-bit 地址 | `0x50` | 已确认 |
| A0/A1/A2 | 全部 GND | 已确认 |
| WP | GND，硬件允许写 | 已确认 |
| 总容量 | 256 Byte | 已确认 |
| Page Size | 8 Byte | 已确认 |
| Word Address | 8 bit | 已确认 |
| 内部写周期 | `tWR` 最大 5 ms | 已确认 |
| SCL 外部上拉 | R50 = 4.7 kΩ → `FLASH_VCC` | 已确认 |
| SDA 外部上拉 | R51 = 4.7 kΩ → `FLASH_VCC` | 已确认 |
| 其它串联链路 | R26/R29、R53/R54 等 0 Ω 网络连接 | 已确认用途为链路，不是上拉 |
| GPIO 基线 | PB6/PB7 Open Drain + `GPIO_NOPULL` + initial HIGH | 已确认当前工程 |
| Software I2C 时序 | half period = 5 us，名义约 100 kHz | 已确认当前配置 |
| AT24C02 Driver | 当前 S03 实现项 | 待施工 |

AT24C02 用于保存少量、需要跨 Reset / 掉电保留的状态数据；Firmware Image 仍由 W25Q64 承担。

## 3. 器件能力与软件影响

| 项目 | AT24C02 约束 | 软件要求 |
| --- | --- | --- |
| 存储组织 | `256 × 8 bit` | 地址范围 `0x00 ~ 0xFF` |
| Page | 32 页 × 8 Byte | 写入必须按 8 Byte Page 拆分 |
| Page Write | 超过页末会在当前页内回绕 | Driver 禁止跨页单事务 |
| Random Read | 先写 Word Address，再 Repeated START 读 | 复用 `platform_i2c_write_read()` |
| Sequential Read | 可连续递增 | Driver 禁止跨 `0xFF` 回绕 |
| Write Cycle | STOP 后内部写入，最长 5 ms | 写后 ACK Polling |
| WP | 本板固定 GND | 无软件 WP 控制 |

## 4. 板级连接

### 4.1 AT24C02

```text
A0 ─ GND
A1 ─ GND
A2 ─ GND
VSS ─ GND
WP ─ GND
VCC ─ FLASH_VCC
SCL ─ shared I2C SCL
SDA ─ shared I2C SDA
```

因此：

```text
7-bit address = 0b1010000 = 0x50
Write address byte = 0xA0
Read address byte  = 0xA1
```

注意：当前 Platform I2C API 接收 **7-bit address**，调用时必须传 `0x50`，不能传 `0xA0 / 0xA1`。

### 4.2 上拉与 GPIO

完整原理图已确认：

```text
I2C_SCL ─ R50 4.7 kΩ ─ FLASH_VCC
I2C_SDA ─ R51 4.7 kΩ ─ FLASH_VCC
```

因此 MCU 内部上拉应关闭，PB6/PB7 使用：

```text
GPIO_MODE_OUTPUT_OD
GPIO_NOPULL
initial HIGH
```

当前生成的 `Core/Src/gpio.c` 已满足：

```c
HAL_GPIO_WritePin(GPIOB,
                  FLASH_CS_Pin | I2C_SCL_Pin | I2C_SDA_Pin,
                  GPIO_PIN_SET);

GPIO_InitStruct.Pin = I2C_SCL_Pin | I2C_SDA_Pin;
GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_OD;
GPIO_InitStruct.Pull = GPIO_NOPULL;
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
HAL_GPIO_Init(GPIOB, &GPIO_InitStruct);
```

该配置与 `platform_i2c_init()` 的运行时契约一致。

## 5. 当前 Software I2C 基线

工程位置：

```text
03_Firmware/Application/OTA_APP/
└─ 03_Platform/platform_mcu/i2c/
   ├─ platform_i2c.h
   └─ platform_i2c.c
```

当前已经具备：

- 7-bit address；
- START / Repeated START / STOP；
- byte send / receive；
- ACK / NACK；
- 最后一个接收字节发送 NACK；
- SCL 实际电平读取；
- clock stretching timeout；
- idle bus validation；
- bus recovery，最多 9 个 SCL pulse + STOP；
- `write()` / `read()` / `write_read()`；
- 原始错误优先保留的 transaction cleanup。

当前缺口：

```c
platform_i2c_probe(platform_i2c_t *i2c, uint8_t address);
```

S03 已冻结其语义为：

```text
START
→ Address + Write
← ACK / NACK
STOP
```

- ACK → `PLATFORM_ERR_OK`
- address NACK → `PLATFORM_ERR_NOT_FOUND`
- 其它总线错误 → 原样传播

`probe()` 只探测一次，不实现 `wait_ready()`。

## 6. AT24C02 Read

读取指定地址采用 Random Read：

```text
START
→ SLA+W
← ACK
→ Word Address
← ACK
REPEATED START
→ SLA+R
← ACK
← data[0]
→ ACK
...
← data[n-1]
→ NACK
STOP
```

对应：

```c
platform_i2c_write_read(
    i2c,
    deviceAddress,
    &wordAddress,
    1U,
    data,
    dataLength);
```

8 Byte Page 边界只约束写，不约束读。

Driver 仍必须限制：

```text
address < 256
length > 0
length <= 256 - address
```

禁止顺序读跨 `0xFF` 后回绕至 `0x00`。

## 7. AT24C02 Write

Page Write 线序：

```text
START
→ SLA+W
← ACK
→ Word Address
← ACK
→ Data...
← ACK
STOP
```

一次实际事务只允许当前 Page 内的数据：

```text
pageRemaining = 8 - (address % 8)
chunk = min(remaining, pageRemaining)
```

例：

```text
write(0x06, 10 Byte)

0x06~0x07 : 2 Byte
wait ready
0x08~0x0F : 8 Byte
wait ready
```

Driver 应使用最大 9 Byte 私有缓冲：

```text
[1 Byte Word Address] + [最多 8 Byte Data]
```

## 8. 写周期与 ACK Polling

AT24C02 在内部 `tWR` 期间可能对器件地址 NACK。

S03 冻结的策略：

```text
probe()
├─ OK
│  └─ ready
├─ NOT_FOUND
│  └─ write-cycle busy → delay 1 ms → retry
└─ other error
   └─ real bus error → return immediately
```

参数：

```text
Datasheet tWR Max     = 5 ms
Poll Interval         = 1 ms
Software Timeout      = 10 ms
```

`5 ms` 是器件规格，`10 ms` 是软件保护窗口。

不能：

- 固定 delay 5 ms 后直接假定成功；
- 无限轮询；
- 用带伪数据字节的普通 `write()` 冒充 ACK polling。

## 9. Raw Driver 边界

S03 AT24C02 Raw Driver 只提供：

```c
platform_at24c02_init()
platform_at24c02_deinit()
platform_at24c02_read()
platform_at24c02_write()
```

职责：

```text
AT24C02
├─ device address validation
├─ capacity/range validation
├─ random/sequential read
├─ 8 Byte page split
├─ page write
└─ write-cycle ACK polling
```

不负责：

```text
Firmware Metadata
OTA State
CRC / double copy / sequence
Journal
Device Manager
Storage Device abstraction
Generic NVM Manager
RTOS bus mutex
```

共享 I2C Bus 的生命周期属于上层 composition，AT24C02 `deinit()` 不调用 `platform_i2c_deinit()`。

## 11. 板测策略

S03 常规板测统一使用：

```text
SEGGER RTT + EasyLogger
```

不额外增加 UART CLI 或 LCD 测试接口。

最小验收：

| Test | Expected |
| --- | --- |
| Init / Probe `0x50` | ACK，初始化成功 |
| Single Byte | 写读一致 |
| In-page Write | 写读一致 |
| Cross-page `0x06 + 10 Byte` | 自动 `2 + 8` 拆分，读回一致 |
| Unaligned Cross-page | Page 边界正确 |
| `0xFF`, len=1 | 合法 |
| `0xFC`, len=5 | 事务前拒绝 |
| Reset Persistence | Reset 后数据保持 |
| Power-cycle Persistence | 实际断电/上电后数据保持 |

失败日志至少包含：

```text
test name
address
length
platform_error_t
expected / actual（发生 compare failure 时）
```

逻辑分析仪仅在 probe、Repeated START、Page Split 或时序异常时作为辅助定位手段。

## 12. 禁止假设

- 不能把 `0xA0 / 0xA1` 直接传给 7-bit Platform I2C API；
- 不能依赖 AT24C02 跨页自动递增；
- 不能允许连续读写跨越 256 Byte 空间后静默回绕；
- 不能把写后地址 NACK 在所有上下文都解释为 Busy；
- 不能让 AT24C02 Driver 直接操作 STM32 HAL GPIO；
- 不能认为 EEPROM Raw Write 具备掉电原子性；
- 不能提前把 Firmware Metadata 和 Bootloader/OTA 业务塞入 S03 Raw Driver。
